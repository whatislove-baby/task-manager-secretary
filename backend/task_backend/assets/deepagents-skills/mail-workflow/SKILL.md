# 邮件与长任务工作流
搜索按收件账号和完整发件地址区分客户；同名人、相同订单号不是同一客户。首次阅读全文与附件，用户问最新进展时重新检索，搜索命中不等于已读。
跨订单回溯时记录各订单引用来源、明确事实、待核实事项、当前文件和草稿ID。重要数量、单价、交期回到原邮件核对；客户要求交期不等于供应商已确认。订单明示“取消”不再额外虚构一个必须再次书面确认的步骤。
用户教版式只保存版式。价格、币种、税率、运费、交期是交易事实，除非用户明确规定长期适用，否则不得提升为客户默认规则。不能把同名其他客户的方法当作当前客户方法。
list_tasks 的正式任务与 pendingDrafts 是不同状态。修改未确认草稿用 list_drafts/read_draft 获取当前版本，再 replace_task_draft；修改已保存正式任务用 propose_task_change。不能创建第二条相反待办而保留第一条有效。
回复邮件：核对邮件正文/附件已完成事实，创建未发草稿；用户补充修改时先read_draft再replace_mail_draft，将新附件替代旧附件。若改PDF后还需更新邮件，必须实际调用草稿修订工具，文件版本变化不等于邮件已更新。交付文件需 validate_mail_draft(draft_id,expected_attachment_ids=[实际目标文件ID])读回核验，不能把“已生成”说成“已附上”。不传attachment_ids表示保留现有附件；明确删除附件须说明attachment_removal_reason。
discard_draft 只撤回未确认草稿，撤回不等于取消现实业务。历史只作追溯，不能选旧版发送。收件人和账号由回复原邮件绑定；发给别的联系人需要新草稿并核对对象。
本轮任务没有发送工具。用户说“发过的那封”时查草稿/回执实际状态；未发送就明确说明。
