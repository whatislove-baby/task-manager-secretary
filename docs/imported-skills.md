# 导入已经开发的 Skill

当前产品以“选择并调用现成技能”为业务扩展方式。AI 不必重新理解全部转换规则、编写和调试业务程序。普通 PDF、Word、CSV 处理继续使用内置文档工具；沟通习惯和报告风格仍可保存为文字经验。

在对话中上传 Skill ZIP，然后说明用途和适用对象，例如：

> 这是已经开发并验证过的活动报名汇总技能。以后职业中心发来同类活动报名表时用它，把统计结果放进回复草稿，先让我检查。

助手调用导入工具，显示包的输入输出约定及实际样例检查结果。首次确认后，新对话可检索、读取并调用当前版本。处理新的同类文件不再重复安装、训练或提供标准答案。导入失败不会让 AI 当场重写客户业务代码；应由开发者修正技能包。

## 包的约定

这是本应用的 Python 技能包协议，采用 SKILL.md 组织说明，并由 Deep Agents 的 SkillsMiddleware 渐进加载。不是任意开源 SKILL ZIP 都可直接运行的承诺。

```text
event-registration-summary.zip
├── SKILL.md              # 用途、触发条件、步骤、边界
├── skill.json            # schemaVersion=1、输入输出、入口和验收样例
├── main.py               # 执行入口，原字节导入
├── app/...               # runtimeFiles 明确列出的模块或资源
└── examples/...          # 正确输入/成品和失败案例
```

skill.json 的 entrypoint 固定为 main.py。runtimeFiles 中的资源按原路径只读挂载到 /work/package。代码从 TM_SKILL_INPUT_DIR 读取声明的输入，在 TM_SKILL_OUTPUT_DIR 写声明的输出；依赖使用应用已有运行环境，不在安装时执行 pip、联网脚本或宿主命令。技能不能获得邮箱凭据和自动发信权限。

输入输出的 name 是约定的文件名。examples 中 inputFiles 和 expectedFiles 在包中映射到相对路径，安装后由应用转成受管引用。首次至少两个不同正常样例、一个错误输入；业务拒绝需要退出码 2、具体错误信息且没有部分输出。工作簿可用 comparison: workbook 比较数据、类型、工作表和模板结构，不以 ZIP 时间戳决定是否正确。

## 公开演示范围

上面的“活动报名汇总技能”是包结构与触发语句的示意，不提供真实业务代码或原始工作资料。公开实习示例使用全合成活动报名 CSV、说明文件与邮件，通过内置文档工具生成简报；它没有把一次文档生成当作已安装脚本技能的证明。实际输入、结果与限制见[公开验收报告](../handover/final-guide/TEST-REPORT.md)。

要演示脚本技能，请使用团队有权公开、已独立验证的示例包，按上述协议准备至少两个正常样例和一个失败样例。不要直接把个人工作文件或内部规则打入公开展示包。

## 验收目标

上传原包 → 说明适用场景 → 验证和批准 → 新对话读取新邮件 → 找到正确技能 → 原附件隔离执行 → 对照预先准备的标准结果 → 输出加入回复草稿 → 创建、审核和更新同一待办 → 再开新对话读回真实状态。

调用成功、样例通过、整条流程通过分别记录；不能互相替代。正式邮件仍由用户在应用中预览和确认发送。
