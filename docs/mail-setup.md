# 多邮箱与本地邮件

本指引对应正式 Python 后端。顶部“邮箱”打开工作台；按服务商支持的绑定方式接入，可保留多个邮箱的独立配置。

## 添加和连接

点击“添加邮箱”，选择一种绑定方式。每个绑定独立保存，可以添加多个IMAP和多个Microsoft 365邮箱，互不替换。

IMAP：在服务商处开启IMAP并取得客户端授权码（若要求）。填写完整邮箱、服务器主机名、端口、安全方式，用户名留空使用邮箱。TLS通常993、强制STARTTLS通常143，以服务商文档为准。填授权码或服务商允许的密码，点击“保存连接设置”，再点击“连接此邮箱”。仅验证成功才显示已连接。相同连接参数留空口令可保留原凭据；更换身份后必须重填。应用验证证书，不提供明文认证。只支持OAuth的服务器不能用普通密码接入。

Microsoft 365：适用于工作或学校组织账号。按[outlook-setup.md](outlook-setup.md)配置公开客户端ID，保存后连接，在系统浏览器完成授权。学校可能要求管理员批准。应用只申请读取权限，不收邮箱密码。

主动断开会清除该绑定凭据，不删除已存邮件或待办；IMAP再次连接需填回授权码。凭据加密保存在data/mail-accounts/<绑定ID>/。Windows使用当前用户DPAPI；Mac使用Fernet加密，主密钥保存在登录钥匙串中。首次访问Mac钥匙串可能需要允许访问。复制data不会复制系统密钥；跨设备无法解密时先完整备份，再重配登录，勿删除tasks.sqlite。

## 选择读取范围

每个账号点“设置”，在右侧加载文件夹，可多选并包含子目录；不选默认收件箱。文件夹窗格固定最小高度，独立滚动。可按最近N天、指定日期起、起止日期、发件人、主题、邮箱未读筛选。点击“应用这些读取条件”后用于后续导入。

回到工作台，勾选要导入的账号，点击“导入所选邮箱”。使用各自默认范围；新账号默认最近7天，包含今天，按本机收件日期筛选。默认“仅导入未保存的邮件”，已缓存的邮件跳过正文下载；取消此项会重新获取，原文变化后清除最新分析标记，已有待办不变。读取不会改变服务器已读状态。

每个账号最多返回200封匹配邮件，达到上限需缩小日期范围继续。按目录收集后排序，不保证跨目录全局最新200封。IMAP身份为目录+UIDVALIDITY+UID，移动或复制可能产生新身份。

## 预设、排除与已知发件人

账号设置中可给当前条件命名，保存多套读取预设。选择预设会填入条件；点“应用这些读取条件”后用于后续导入。包含文字与不包含文字同时生效，忽略大小写；多发件人包含列表任一匹配即可，排除列表任一匹配则跳过。导入后保存已知发件人，可勾选或按行自行添加。导入区显示账号当前实际日期范围。

## 本地归档和删除

正文保存在data/mail.sqlite，离线可查看。附件只显示名称、类型和大小等信息，不下载或分析附件内容。可创建本地文件夹、批量移动；移除文件夹后邮件回到未归类。删除本地邮件需确认，会删除正文行，保留独立的导入／分析收据及已知发件人。后续同步即使关闭“仅导入未保存”也不会恢复已删除邮件。邮件去重使用绑定及邮箱稳定ID；IMAP移动、复制或UIDVALIDITY重置可能形成新身份。

AI产出和会话独立保留，可能仍引用此前分析的文字。删除本地邮件不删除这些产出、已创建待办或服务器邮件。若不需要某个对话，可在AI历史删除对话记录；已生成草稿及待办保留。SQLite启用secure_delete用于清理删除行，不承诺对已有备份或SSD物理残留做安全擦除。

## 可暂停的后台处理

导入与分析启动后立即返回后台任务进度。“暂停”请求在处理检查点生效，已发出的网络请求可能仍会完成和计费；点击“继续处理”从已保存的位置继续。收起邮箱窗口后仍可操作待办。完成后可返回查看结果；应用退出时任务保留，下次主动继续。

已完成导入不会重复下载正文；失败导入可再次发起并只补未保存邮件。AI默认逐封独立请求，超长单封分段处理；部分长度或格式错误会缩小分段，限流／网络问题有限重试，失败后继续不会重发已保存的成功段。单任务最多1000封、12MiB原文、2000段，每封合并结果最多100项草稿。模型明确报告回复被截断时，任务报错，不保存该不完整结果。只有正文完整且全部分段成功，邮件才记为已分析。

批量勾选不表示把不同邮件拼到同次分析请求。草稿来源始终绑定原邮件，可在备注中回看依据。新分析不会自动关联已有Canvas任务或其他分析生成的待办。

## AI对话与本地记忆

先在AI服务设置中填写HTTPS基础地址、模型ID和API Key。OpenRouter基础地址可填`https://openrouter.ai/api/v1`，模型ID以账号实际可用的为准。保存配置只验证字段，不代表服务已连接；请先用短文本生成一次结果。当前Python通过提示要求JSON并校验返回值，没有额外启用JSON mode或强制关闭DeepSeek思考模式；各模型的可用性、耗时和输出质量需用真实请求确认。

勾选邮件，填写“给AI的操作要求”，点击“分析已选N封”。结果可在“AI对话历史”中打开，选择“审核本轮待办草稿”，核对标题、日期及原文依据后再保存。分析不会自动新增待办；同一分析重复确认不会重复添加，但重新分析同一邮件会产生新结果，再次确认仍可能创建重复任务。

返回原会话追问时，程序重新读取本会话选中的本地邮件正文，带上最初要求、完整草稿信息和会话历史；长历史用摘要压缩，完整日志仍在本机。原邮件及最初要求等来源上下文最多24000个UTF-16字符（多数常用汉字计1，部分emoji计2）；超过范围会明确要求减少邮件后重新分析，不会静默截掉原文继续回答。原文已删除或未完整读取时，模型会收到相应说明。新建文字对话最多20000字符，每轮追问最多4000字符。

仅导入或打开邮件不会发送给AI；主动分析、追问才会发送相应原文和历史。邮件的“已分析”与服务器已读、待办是否保存分别记录。现有自动化测试使用合成邮件和受控模型响应，不代表学校邮箱或OpenRouter真实账号已验收。

独立实测记录：2026-11-20 的 QQ 单封收发（本地历史材料未随仓库发布） 与 OpenRouter 纯文本起草（本地历史材料未随仓库发布） 分别通过；后续三封邮件全流程（本地历史材料未随仓库发布）又完成真实导入、AI提取、逐项审核保存与应用内日历核对。首次B格式校验失败的原响应未保留，具体原因未证实；补齐日期契约、细化错误并修复失败任务恢复入口后，从原任务1/3继续至3/3，未重跑已完成的C。按[复测步骤](self-test.md)操作；其他邮箱、真实Canvas与学生交接仍待验证。

对话、检查点和摘要存data/mail-operations.sqlite，正文、导入收据、预设和归档在mail.sqlite。均为本地明文数据；凭据保持系统加密。JSON待办备份不包含这些内容，退出整个应用后完整备份data。

## 备份与排错

JSON待办备份不含邮件、分析历史或登录配置。退出整个应用后，完整备份data文件夹可同时保留邮件库；登录凭据在其他系统账号／设备上需要重新配置。

连接失败先核对服务器、加密方式、授权码、服务商访问开关，不关闭证书验证。部分邮件导入失败会列出账号提示，已成功的仍保留；缩小范围再试不会重复保存。过大的邮件请在原邮箱客户端查看。

本分支新增的「写邮件」使用独立的 AI 写作与 SMTP 发送流程，详见[邮件写作与发送](mail-compose.md)。读取成功不等于 SMTP 已验证；需另外配置发信服务器，并在预览后主动确认发送。根据来信起草时，所选原文也会发给用户配置的模型服务。
