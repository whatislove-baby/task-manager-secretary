把邮件里的事情，接着做完。

一个以对话为入口的本地 AI 助手，把收件整理、资料处理、报告回复和待办管理连在一起。

秘书式收件整理

在固定主对话中刷新邮件，展开需要处理的事项，折叠普通通知和疑似垃圾邮件。

对话驱动的工作台

直接说需求，结合邮件、附件与本地资料查找上下文；信息不清楚时继续澄清。

文档处理与回复

读取 PDF、Word、CSV，生成或修改文件副本，检查页面后加入邮件回复草稿。

待办与课程日历

从邮件提出待办，处理截止日期、改期或取消；确认后更新应用内日历。

历史与经验复用

检索历史邮件、任务和已批准的文字经验；导入已有 Skill，测试并批准后复用。

复杂任务独立处理

耗时文件工作进入子对话，保留来源和处理进度，主对话继续接收新的需求。

可以怎样使用

学生：从课程邮件到截止提醒

“这门课最近有什么要处理的？把 Project 截止记下来。”

刷新与分类 → 查看课程原信 → 提出待办 → 用户核对 → 本地日历。后续收到改期邮件，继续更新同一任务。

实习生：从附件到报告回复

“按这份资料做一页报名简报，给我 Word 和 PDF，先存草稿。”

读取邮件、CSV 与说明 → 子对话生成报告 → 检查内容与页面 → 将两份文件加入回复草稿 → 用户预览发送。

怎样从对话走到结果

  1. 用户入口React / Electron · 固定秘书、任务对话、文件和日历
  2. Agent 执行Deep Agents · 任务规划、工具调用、文档子助手
  3. 状态与恢复LangChain 工具接口 / LangGraph 检查点、澄清与恢复
  4. 业务与保存Python · 邮箱、文档、任务、草稿、经验与 Skill
  5. 用户审核查看原文和文件，确认待办变更、技能版本与邮件发送

当前使用范围

当前以 Mac 版本为主要验收环境。定时收信需要电脑在线；日历保存于应用内。PDF 支持读取、页面操作与生成副本，复杂原版式修改需核对。模型分析通过用户配置的 OpenRouter API 完成。
