# 产品范围 · 后端规则基线

更新时间：2026-10-29。

状态：后端基线完成后，用户提供了周视图、日期列表、右侧详情树的前端方案，现已按 docs/interface.md 实现。是否通过以 verification.md 的实际验证范围为准。旧前端原型保存在提交 b162474，不作为当前发布版本。

## 已确认的首版范围

- Windows 本机桌面应用，独立项目；统一管理「待办」，不区分任务与日程，不设优先级。
- 每项待办包含：必填标题、可选截止时间、可选备注、是否完成。
- 截止时间支持三种精度：不填、仅年月日、精确到分钟。日期不能被伪装成某个确定时刻。
- 子待办与父待办结构相同，支持无限逻辑层级；不存在产品层面的固定深度限制。
- 默认勾选父项完成会完成全部后代；所有直接子项完成后父项自动完成。用户可以修改该联动配置，当前以两个独立开关提供。
- 删除父项时，父项与所有子孙一起进入回收站。
- 新建表单默认今天、仅日期（2026-10-29用户更新）；子项可切换为共享父项截止，继承时不显示重复日期。自行设置的子项显示自己的截止时间，允许晚于父项但给出非阻断提醒。父项修改后，仍在继承的分支跟随变化。
- 取消父项的已完成状态只恢复父项，所有后代的完成状态保持不变。
- SQLite 是主存储；默认数据目录为应用目录下的 data。用户将在非 C 盘放置应用。JSON 只用于配置或导出，不能替代主数据库。
- 目标目录不可写时说明原因并让用户处理，不能静默改用 C 盘用户目录。
- 用户自行配置云端 Chat Completions 兼容 API。输入支持粘贴文字和导入 .eml。AI 只生成可编辑草稿，用户确认后才能保存。
- 本地模型和 Obsidian 插件不在首版。

## 当前采用的工程默认值（可后续调整）

用户已确认的产品规则优先；以下补足存储与异常处理边界，后续调整需保留已有数据。

### 截止时间

- 将「继承」「明确不设截止」「自行设置」分开保存。子项手动清空表示明确不设截止，不会立即被父项再次填上；另设恢复继承操作。
- 采用动态继承：继承链向上找到最近的显式值或显式空值。父截止修改后，仅仍处于继承状态的后代自动跟随；有自己设置的节点及受其控制的继承分支保留自己的规则。
- 后端未传截止时根项默认不设截止、子项默认继承；前端新建表单按最新规则显式预填今天、仅日期。移动子树后，继承部分跟随新父项，显式设置保持不变。移为根时，原继承值转为不设截止，并在操作预览中显示变化。
- 日期精度表示该日，不自动写成 23:59；分钟精度表示指定时刻。仅日期的待办在该日结束后才算逾期；分钟截止在指定时刻过去后逾期。
- 晚于父项的比较：双方均精确到分钟时比较实际时刻；只要一方仅有日期，则按本机时区对应的日历日比较。同一天不因精度差异认定谁更晚。任一方无截止则不比较。
- 提醒是允许继续保存的非阻断提示。创建、编辑、移动、父截止变化及恢复均检查受影响的父子关系；批量操作汇总提醒，不弹出大量逐项窗口。

### 完成联动

- 采用两个独立全局开关，默认都开：①手动完成父项时向下完成全部后代；②直接子项全部完成时向上自动完成父项。
- 向上判断只计未进入回收站的直接子项；至少存在一个直接子项才触发，空列表不会让叶子自行完成。向上变化可以递归到祖先。
- 自动向上完成不额外触发向下批量完成；向下联动只由用户明确执行完成操作触发，避免产生意外的跨分支修改。
- 已确认取消父项完成只取消该项，保留后代现状。另有设计建议：取消子项完成时，若向上开关开启，则取消已完成祖先的完成状态，保留兄弟项；祖先行为仍为草案。
- 明确取消父项完成后，即使现有子项仍全部完成，也不立即把它自动勾回；直到下次相关子项状态或树结构发生变化才重新判断。
- 开关变更仅影响后续操作，不追溯改写整棵树。关闭联动时允许父子完成状态不同。

### 回收站与树结构

- 单次删除按当前有效子树形成一个回收批次，原父子关系及完成状态保留；早已删除的分支保持原回收批次。
- 默认以批次为恢复单位，恢复该次删除的整棵子树。原父项仍有效则恢复原位置；原父项不存在或仍在回收站时，默认恢复为根，并明确提示位置及继承截止的变化。
- 恢复保留各项原有完成状态；若恢复未完成子项且向上开关开启，则按取消完成规则重开祖先。新增、删除、移动等结构变化也检查受影响的有效父项，非空直接子项全完成时触发向上完成。
- 回收站不参与日常列表、完成汇总和逾期筛选。首版不自动清空、不提供永久删除，后续如需支持再明确规则。
- 移动节点不能指向自身或自己的后代；禁止跨越回收状态移动。逻辑无深度上限，超出实际资源承受能力时整体拒绝操作并说明原因，不能截断子树后部分保存。

### AI 与存储

- 模型返回内容和导入文件均按不可信输入校验。缺失或有歧义的日期保留为空，并提示用户；不擅自增加优先级、开始时间等已废弃字段。
- 草稿阶段可编辑标题、备注、截止和层级；确认时再次验证整棵草稿树，一次事务保存。取消、接口错误、解析失败或任一条验证失败均不保存。
- 建议应用启动时先验证 data 可创建、可写以及 SQLite 可正常使用；失败则阻止数据操作并显示修复路径。不静默迁移、不创建备用数据库。
- 密钥不进入导出、不在界面或日志中回显，建议使用 Windows 提供的加密能力保存于 data；JSON 配置不保存明文密钥。
- 首版暂不含邮箱登录/同步、跨设备同步、重复规则和后台提醒；这些是范围草案，不等同于所有截止提醒能力都被删除。

## 已收敛的关键规则

未手动设置的子项仍受父截止约束、仅不重复显示；取消父项完成只恢复该项。后端实现动态继承，父子完成联动开关可独立配置。

## 新增前端规则

## Canvas 接入（2026-10-30）

用户确认：配置Calendar Feed后，每次主动点击一次同步即自动拉取并入库；不用AI，不逐项确认。远端标题/截止更新跟随并在同步面板列出更新提醒，保留本地备注和完成状态。重复去重、缺项不删、回收不复活。仅同步订阅实际提供的内容，完成状态不回写Canvas。


### Canvas 长说明（2026-10-30）

来源完整说明与个人备注分开保存；详情默认只提供阅读入口与原事项链接，完整说明在独立阅读层查看、滚动、选择复制，离线也可阅读。来源说明及链接随同步更新并列出变化，不覆盖个人备注。旧版备注原样保留，新导入个人备注为空。单条事项异常不阻止其他有效事项同步，问题在同步窗口逐项列出；全局格式/网络/资源错误仍不写库。当前不使用AI生成摘要。


Canvas 同步仅提交截止日期为本机今天及之后的事项；分钟按本机时区换算日历日，不以当前时分排除当天事项。在入库前重新确定今天，避免网络请求跨午夜后导入昨日事项。已保存历史项不自动删除；同步结果expired计数并包含于skipped，不列为异常。此规则不修改底层通用ICS解析范围。


## 学校 Outlook 优先（2026-10-30）

首版优先学校Microsoft 365 Outlook：官方浏览器登录、可展开文件夹树、多选与子文件夹范围、日期/发件人/主题/未读组合过滤，默认条件按账户保存。读取与AI整理分别操作，单封生成草稿后确认保存并防重，保留原文来源。之后再适配其他邮箱。真实学校授权须实际账号验收，管理员策略不可由本机程序绕过。当前多账号与通用IMAP范围以本文后续规则为准；后台定时读取未实现。


### 绑定方式调整（2026-10-30，覆盖先按邮箱品牌适配的安排）

用户确定按绑定方式分类，不按邮箱品牌。当前实现IMAP授权码／密码和Microsoft365浏览器授权；用户自行填写相应服务器与账号，共用读取、默认筛选和AI草稿。不保证任意邮箱支持任意方式，IMAP必须TLS／STARTTLS且服务商允许该认证；仅配置成功不等于连接成功。已有微软配置沿用，不删除原待办。


### 多账号、本地邮件和启动偏好（2026-10-30，当前规则）

允许绑定多个IMAP及Microsoft365邮箱，同时筛选本地邮件、选择跨账号内容分析。按账号保存默认条件，默认最近7天且只导入未保存正文。本机保存正文与分析结果，不保存附件，断开不删本地内容。用户可指定AI操作要求，分析部分或全部筛选邮件，草稿确认才成为待办。分析失败不标成功，空待办总结也保存分析记录，已分析可重开，重复确认不重复入库。

可选择Windows开机启动、启动时打开悬浮窗、关闭主窗到托盘／退出所有进程。默认不自启动、不自动开悬浮窗、关闭主窗到托盘；托盘明确退出结束整个应用。当前资源限额和本地备份范围见README及mail-setup.md。


### 邮件后台处理、本地记忆及归档（2026-10-31，当前规则）

导入／AI可主动暂停与断点继续，收起邮件界面后继续处理待办，完成提供返回入口。邮件状态只有未分析／已分析。账号支持命名读取预设、文字包含／排除、多发件人及已知发件人选择。本地自建文件夹归类；删除正文时保留独立导入／分析收据，常规重导不复活，不删除服务器邮件。

AI按会话保留完整输入、答复与草稿产出，可重新打开追问；长历史使用摘要上下文，原始记录保留。较多邮件自动小批分段，支持长度失败缩批、有限网络重试及检查点，不把部分成功标为全部完成。悬浮窗空白区域点击穿透，仅实际图案及可见控件交互。当前资源边界以README和mail-setup为准，先前200封AI／24万字符及第三状态限制已被当前规则取代。
