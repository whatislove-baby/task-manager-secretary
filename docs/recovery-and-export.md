# 执行恢复与对话导出

这两项接在已有秘书/任务对话里，沿用同一分支和原有执行架构。

## 执行失败后

在对话底部查看恢复卡。它区分连接中断、请求限流、认证问题、配置问题、执行限制和模型回复未完成；旧记录或无法明确分类的失败显示通用指引。

- **继续本轮**：沿用同一执行记录，保留已有文件和草稿。系统尝试根据现有检查点继续，不能保证所有模型请求都不重复。
- **打开模型设置**：在认证、配置等需要核对设置的情况下出现，打开现有“偏好与数据”窗口。
- **结束本轮**：停止当前轮次，之后可以调整要求重新发起。不会删除已有文件或草稿。

更换服务地址、模型或 API 密钥后，原有配置一致性检查仍生效：需结束当前轮次后重新发起，不能直接将旧检查点切换到另一套配置。没有配置密钥时，发送前的提示也提供设置入口，输入内容保留。

停止收尾过程中按钮不可重复点击。暂停与取消的原有行为保持不变；不会自动重试、审批或发送邮件。

## 导出完整对话

打开要导出的对话，点击顶部 **导出对话**。

- **复制完整对话**：复制当前对话的全部已保存问答，便于粘贴到报告或交接消息。
- **保存 Markdown**：选择保存位置，生成 `.md` 文件，可用常见文本编辑器打开。
- **附上来源与产物名称**：按需附上每条回答关联的来源和产物名称；默认不勾选。

导出包含对话标题、时间、按顺序排列的用户与助手内容。当前尚未完成的回复明确标记为未完成，等待补充的问题及选项也会保留；已保存为正式回答的内容不会再追加一份。导出时重新读取所选对话，正在执行的任务只导出读取时已有的内容。

仅导出当前对话；子任务需分别打开导出。内部工具事件、隐藏上下文、设置凭据和附件内容不在导出范围内；对话正文中的原有文字和引用按原文保留。取消保存不会修改现有文件。覆盖已有文件时，先完整写入同目录临时文件，再替换目标；写入或替换失败时保留旧文件。

## 实现边界

只新增可选失败分类和一个受限的桌面导出接口。保存路径由系统文件窗口选择，界面不能提交任意路径或文件正文。没有改数据库表结构、调度队列、模型依赖或人工审核流程。
