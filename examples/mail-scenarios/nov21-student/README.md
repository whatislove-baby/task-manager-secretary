# 学生邮件长链路演练 · 1121

这是一套**输入与预期**，不是已通过的测试报告。12封邮件模拟两门虚构课程，不改变用户真实课程安排。统一主题前缀为 `[TM演练 1121]`，邮件正文角色可不同；实际发件地址必须是已连接并授权的真实邮箱，不伪造老师、同学或营销方身份。一个实际邮箱不能验证不同真实发件人的归档能力。

`messages.json` 保存完整投递内容，`expected.json` 保存可核对答案。里面的两个附件由投递执行者正常生成：文字 PDF 评分表和 Markdown 数据清洗说明；E11 提到的 FAQ 故意不附文件。发送时只使用 subject、body 和生成后的实际附件，不把 expected 或 intentional_failure 元数据加进邮件。

## 一步一步人工验收

引导者每次只带用户做一步，确认观察结果后再继续。前几步不保存正式任务，也不发出回信；这样问题容易定位。

### 第1步：先确认邮件到达和导入

在新版应用打开“收件箱”，点击“收取新邮件”。系统收取所有已连接邮箱最近7天的收件箱，跳过已经保存的邮件，无需配置测试预设或逐封勾选。完成后在搜索框输入 `TM演练 1121`，核对E01至E12是否齐全，E02有PDF、E03有Markdown。搜索只是方便核对这一批，不是收信的前置步骤。此时先不点击保存待办或发送回信。

只有真正看到了来信，才记读取通过。SMTP“已接受”不是用户收件箱已收到的证据。自动整理已启用时，本批可能先出现分类和草稿；这本身不代表已保存正式任务。

### 第2步：核对跨邮件理解

在新对话输入：

> 只看主题包含“TM演练 1121”的这一批邮件。帮我总结 TEST101 的 Project 2 最新提交和展示安排、当前进度，以及已取消的安排。列出依据，信息没有证据就写待核实，先不要创建任务。

核对：提交11月28日23:59香港时间，展示11月29日14:00、R-305；组内11月24日排练取消，无新日期。清洗完成；幻灯片仅初稿完成、待核对；误差分析未完成、交接未进行。源码/README/打包状态未知。不能混入TEST202。

### 第3步：检查附件真读和失败处理

继续问：

> E02 评分PDF要求附录保留几条失败样例？每条必须包含什么？四部分分值分别是多少？请实际读附件再答。

核对：3条；原始输入、错误表现、改进建议；40/30/20/10分。打开它给的来源，确认是实际文件。

再问：

> 按 E11 的 FAQ 附件告诉我误差分析还缺什么。

正确行为是说明没有找到FAQ附件，不能判断具体补充要求。不得把E02评分PDF冒充FAQ，也不得编造FAQ要求。

### 第4步：检查多轮澄清

另开一个新对话，避免前一轮TEST101上下文替用户消除歧义：

> 帮我处理这批邮件里 E08 的材料请求，准备一份回复，先不要发送。

模型应先弄清是哪门课及材料范围。回答：

> 指TEST202的接口设计说明。只起草回复，询问对方说的是哪一个周五；先不要发送。

核对后续仍围绕原来请求，不重头问同一个问题，不把TEST101的11月28日改期套到TEST202，不自行承诺交付。

### 第5步：生成文件和带附件草稿

回到TEST101对话：

> 根据已经查证的信息生成一份Markdown进度清单，再起草给模拟助教的进度邮件，把这份清单加入草稿附件。不知道的状态写待核实。先不要发送。

打开成果卡核对文件存在、内容正确、邮件附件是同一份生成文件。关闭后重开应用，打开最近对话，确认来源和成果还在。草稿不是发信，收件人仍需用户核对。

### 第6步：最后才验收待办审核和日历

> 查看现有待办后，为本批TEST101仍需要做的事准备待审核草稿，不要重复数据清洗，也不要添加已取消排练。只生成草稿，先不要保存。

检查草稿后可只保存1项，便于观察日历与状态。当前Agent新增草稿工具只支持日期级；如果23:59丢失，需要在审核时补齐并记为现有限制，不能说它自动保留了分钟精度。已有旧任务的更改或取消需人工编辑，Agent目前没有自动合并或删除旧任务工具。

最后再讨论真实发信测试，先在预览里检查收件人、正文与附件。不要为完成演练把无关用户或真实老师加入收件人。
