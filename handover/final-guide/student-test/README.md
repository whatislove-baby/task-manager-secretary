## 保留的问题与原因

1. 第二、三轮把邮件 UTC `receivedAt` 的00:15、00:10写入中文回复，没有注明UTC；原合成信件对应香港08:15、08:10。实际被修改的任务时间均使用正确的香港时区。**这是回复文字的时区标注遗漏，不是本次DDL保存错误。**
2. 第四轮先正确叙述讨论改期后取消，却又说“那次讨论没有被记成待办（取消后也没有残留）”。实际它曾创建、改期、取消。代码中的 `list_tasks` 只查询当前任务，没有向模型提供已删除历史参数；模型错误地从“当前列表没有”外推“从未建过”。应当只说当前活动任务里没有讨论，不能把缺少查询证据变成历史事实。此问题包含工具信息范围和模型错误推断，**本轮没有改代码或重发纠正轮次掩盖它**。

这些问题没有改变真实任务状态，但影响用户信任和解释精度。`summary.json`因此将结构通过与语义不完全通过分别记录。

## 历史查询问题修复与第五轮复测

第四轮错误已保留。随后增加 `list_tasks(include_deleted: bool = False)`，默认行为仍不含回收站；历史回溯可显式包含回收站任务。返回明确查询范围、`createdAt/deletedAt`、生命周期和原始due。已删除任务的effectiveDue为空，不推断失效的父项继承时间。只有匹配当前trashBatch的已批准取消回执才标记`cancelled`，手工移到回收站标记`trashed`；两者都不会自动当成完成，也不会被查询恢复或修改。系统和工具说明明确“当前列表缺失不证明从未建立”。

42项相关测试通过，其中5项新增覆盖：默认查询不变、历史读取且数据库无写入、实际取消不等于完成、恢复后手工重新删除不错误归因旧取消、分页/关键词/完成筛选、已删除继承截止，以及官方Agent工具参数传递。

第五轮在同一持久资料库、新会话中使用**与第四轮完全相同的用户提问**。模型实际调用`include_deleted=true`，读到原讨论ID和取消回执；自然回复说明“讨论那条”状态已取消、有对应已批准记录，并明确“它不是‘已完成’”，同时正确叙述原约→改期→取消、最终作业截止和软件尚未勾完成。没有新增产物或改动任务，未再使用“从未建过”的错误推断。

第五轮原判分器有一项假阴性：它要求“曾经/回收站”等特定存在性词，而正确回答用具体任务链接和取消回执表达该事项确实存在。原`turn-05-verification.json`及回答**未改写**；`turn-05-independent-review.json`保存独立复核、原文件/回答哈希和原因，判分器后续增加“明确引用实际任务ID”的等价证据。没有为此重跑模型。第五轮源码启动哈希与完成后复核一致。

此次修复解决的是第四轮历史查询/解释缺口；第二、三轮旧回复的UTC标注遗漏仍作为历史问题保留，未因此宣称所有自然语言细节已完美。
