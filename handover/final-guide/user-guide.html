第一次使用

先连接服务，再从对话开始

退出旧版应用，打开这次交付的 Mac 版本。所有操作围绕聊天进行；邮件、文件和待确认事项放在侧边栏。

01

认识主界面

默认进入固定的“秘书”主对话；中央输入框用来说明需求。侧边栏保留普通新对话和最近对话。你不需要先选课程或创建空间。要处理已经保存的邮件或文件，可以直接说名字，也可以明确附在这一轮。

02

添加这一次要用的材料

点击输入框左下角的加号，选择邮件或上传本地文件。网页链接可以直接粘贴到对话里，但当前应用没有通用联网浏览能力；关键内容请提供原文或文件。

03

打开设置

设置页集中管理模型、邮箱、定时整理、Canvas 和技能库。下面先连接模型与邮箱。

04

配置模型与 API

进入“模型与 API”，找到“AI 服务”。OpenRouter 服务地址填写 https://openrouter.ai/api/v1，模型名称使用账号实际支持的完整 ID。填写自己的 API 密钥后点“保存服务配置”。截图特意留空，没有展示或复制真实密钥。

05

连接邮箱

进入“邮箱账号”添加邮箱。QQ 邮箱需要在邮箱网站开启 IMAP/SMTP，并用授权码连接；收信 IMAP 与发信 SMTP 要分别核对。普通邮箱可按服务商要求配置。不要把登录密码或授权码发到聊天中。完成后回到收件箱点“收取新邮件”。

06

按固定时间自动整理

在“定时整理”选择已连接的 IMAP 邮箱，核对时间、首次读取天数、每轮分析数量后保存启用。可设香港时间 09:00、18:00。它在本机运行；电脑关机或睡眠时不会成为云端 24 小时服务，恢复后再检查补跑。整理不会自动发信或删信，待办仍需审核。

秘书主线 · 日常入口

先整理收件，再推进具体任务

每次打开应用都会回到固定的“秘书”对话；普通“新对话”仍可使用。下面的虚构邮件从空收件箱经实际邮件读取流程导入，测试以本地模拟代替外部邮箱服务器，分类和任务处理使用真实 API。截图副本没有连接账号，不会发信。

01

用一句话查看新邮件

在秘书对话中说“刷新一下”，助手会收取已连接邮箱并整理邮件。本轮收件结果放在回复中；需要处理、重要和待核对事项先展开，普通邮件与疑似推广折叠。分类不是删除操作。

可以这样说

刷新一下，告诉我有哪些事情需要处理。

02

被折叠的邮件仍可以查看

点击分组标题可以展开原邮件。分类仅是助手的判断；发现分错时可以把该邮件带入对话，直接说明应该如何分类。旧卡保留当时的整理记录，后续更正不会改写历史。

可以这样说

这封不是垃圾邮件，是我需要跟进的活动通知，请重新分类。

03

重要内容回到原文核对

点击整理卡里的邮件标题打开完整正文。需要讨论时，用行末箭头带入当前对话，再补充问题；已有输入不会被替换。

04

让复杂工作进入任务对话

可以要求秘书把一项文件处理工作单独推进；回复中的任务卡会打开对应子对话，卡片的“实时状态”和查询时间直接读取当前任务记录；聊天文字保留生成回答时的情况。也可在秘书输入框写好完整需求，点击“单独处理这件事”。成功后任务开始排队，已提交的父输入会清空，失败则保留原文和附件。

可以这样说

请把这封邮件的报名表整理成一页简报，给我 Word 和 PDF，放进回复草稿，先别发送。

05

保留最初要求和参考资料

任务页面可以展开“本次任务”，核对原始要求和绑定的邮件、文件。接着在这里补充细节或检查成果，不必重复提交任务。任务完成不等于已发送，文件与邮件仍需要核对。

06

回秘书继续处理其他事情

点击“返回秘书”回到日常主线。任务卡显示“本轮完成”后可点“查看结果”；这不表示邮件已发送。展开“任务对话”查看各项工作的状态，点一项即可继续；需要补充信息、失败或暂停都会保留状态，不会被当成完成。

示例一 · 学生也适用的日程管理

从课程通知到已保存的日历事项

例如收到虚构课程的提交或小组会议通知，先核对邮件，再让助手整理提醒。这里关注“待确认”与“已保存”的区别。示例合成邮件已预先导入本地；模型分析使用真实 API，本轮手册回放没有实测 IMAP 收信。

01

收取并找到课程邮件

点击“收取新邮件”，程序会收取已连接邮箱最近 7 天的新邮件，自动跳过已导入邮件。可以搜索主题或发件人；点邮件查看原文，点右侧箭头带入对话。截图展示预先导入的本地示例邮件，尚未连接真实邮箱。

02

把邮件带入对话

输入框上方会出现已选邮件。说清楚你想做什么即可，不需要手写日期格式或任务 JSON。

可以这样说

帮我看一下这封课程邮件，把需要参加的活动记到日历里。

03

先看来源，再看草稿

助手的回答中可以打开来源邮件，也可以展开工具执行记录。下方待办卡片只是草稿，此时日历还没有被改动。遇到不明确的日期或对象，直接在同一对话补充。

04

在待确认里集中审核

侧边栏“待确认”列出任务建议和邮件草稿；也可以从对话卡片直接打开。它们不是自动生效的最终结果。

05

核对日期后确认保存

检查标题、日期、具体时刻和原文依据；可以直接改字段，再点击“确认保存”。关闭窗口不会代表同意保存。

06

到日历核对实际结果

保存后进入“日历与待办”，切到事项所在周并点任务，核对保存的时刻。收到改期邮件后，在原对话要求更新同一事项；审核变更后再检查日历，避免重复新建。

可以这样说

这次活动改期了，请按新邮件更新刚才那个提醒，不要另建一条。

07

改期时先比较前后变化

收到后续邮件后，助手针对同一事项提出变更。审核卡会列出变更前和拟变更后的时刻；确认后更新原任务，不需要新建另一条。

示例二 · 实习中的资料汇报

从邮件附件到报告与回复草稿

校园职业中心的同事发来合成活动报名表与说明，让助手汇总重点、整理表格并生成可编辑的 Word，再导出 PDF。下面展示实际模型流程的文件与草稿。示例邮件与附件预先导入本地，截图来自真实 API 运行后的持久化结果；本轮没有实测 IMAP 收信或发送邮件。

01

描述用途，给出必要材料

选择相关邮件，或上传说明文件、CSV 和已有模板。说明给谁看、希望多长、重点是什么；不需要提供排版参数。已有公司模板要直接附上并说明沿用。

可以这样说

帮我根据职业中心同事的邮件和报名表，写一页报名简报，用小表列出各场报名数和剩余名额。给我 Word 和 PDF，并放进回复草稿，先别发送。

02

打开 PDF，逐页核对

点击生成的 PDF 卡片，再点“预览页面”。检查数字、标题、表格、分页和来源。工具显示检查完成仍不代替业务审核；觉得某处不对，可以说“第二场的剩余名额请核一下，保持表格格式”。

03

保留 Word 作为修改来源

Word 保持可编辑，PDF 从当前 Word 直接转换，保留列宽、图片和分页。修改正文后应生成新版本，并检查新 PDF。复杂模板、缺少字体等仍可能造成转换差异；扫描 PDF 的改写可能需要原始 Word 或额外处理。

04

核对邮件对象和文字

打开“邮件草稿”卡片，检查收件人、主题、正文和事实表述。不要只看助手说“已准备好”，要看实际草稿内容。

05

核对两份附件，再决定是否发送

附件区应实际出现当前 Word 和 PDF。打开检查、确认版本后，才进入“预览并准备发送”，然后由你确认发送。手册截图的临时资料未连接发件邮箱，发送按钮不可用；截图过程没有发信。

需要时再用

把成熟的处理方法交给助手

导入已经开发好的 Skill

在对话加号中上传技能 ZIP，说明它的用途、哪些活动或邮件应该使用。按界面的验证结果审核并安装，以后类似任务可调用已批准版本。当前是本应用的 Python 技能包协议，不保证任意第三方 ZIP 都能直接运行。

可以这样说

这个技能用来汇总活动报名数据。以后处理同类活动时使用，结果先给我检查，再放进回复草稿。

语气偏好、报告结构等经验可以保存成文字方法；严格计算和重复文件转换更适合已验证的脚本 Skill。普通报告生成不需要先安装 Skill。

只要 PDF 中的几页

可以说：“把这个 PDF 第 1、3 页另存一个副本。”助手可按原页另存新 PDF，原件保留；这和改写页面正文是两种不同操作。

遇到问题时

从具体状态继续

模型名称不支持
回到 API 设置，使用当前账号可用的完整模型 ID；服务地址与密钥必须属于同一个服务。
收件箱没有最新邮件
点“收取新邮件”，查看连接状态与收取结果。也可以在秘书对话里说“刷新一下”；普通对话搜索的是已经导入本地的邮件。
报告还在处理
展开执行记录看当前步骤；可以暂停，再继续执行。已保存的文件会保留。不要在未完成时把局部文件当成最终交付。
文件排版或数字不对
指出具体页面、图表或段落，必要时提供参考模板。让助手修改当前版本，再检查新版与草稿附件。
提醒没有出现在日历
先看待确认是否已经保存，再切到截止时间所在的那一周；聊天里出现草稿不代表日历已经更新。
