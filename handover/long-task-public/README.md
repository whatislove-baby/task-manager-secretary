# 十五轮任务过程测试

打开 [TEST-LOG.html](TEST-LOG.html) 查看逐轮过程。每轮分别展示用户原话、新出现的邮件、预期、实际观察、AI完整回复、工具参数、持久状态和独立用户审核。结构检查通过不等于语义全部正确；发现的问题会留在对应轮次。

15轮基线已全部自然完成，累计模型处理829.21秒（约13分49秒，不含独立审核等待）。独立语义验收为**9轮通过、6轮部分通过**，不能描述成“15轮全部通过”。150项证据一致性检查通过（149项执行记录与状态检查，加1项原始截图及日志哈希完整性检查），见 [independent-timeline-audit.json](independent-timeline-audit.json)；它不替代人工语义结论。

所有人物、课程邮件、项目选题和要求均为合成内容。测试者只给正常自然语言请求，不给标准答案或工具调用方案。模型每轮只能看到截至当轮揭示的邮件。完整资料位于 `fixtures/scenario.json`，它留在测试侧，不作为模型上下文整包发送。

前十二轮在同一对话中，涉及选题、分工、提纲改期、报告延期、展示调整和另一个同名老师。第十三轮换新对话，检查同发件人已审核经验的复用；第十四轮再换新对话，检查同显示名但不同邮箱时不套用旧偏好；第十五轮换新对话并把参考时钟设为三个月后，查回持久邮件和任务。它是模拟时间间隔，不代表机器真的持续运行了三个月。

待办与经验有审核边界。模型先生成草稿或变更提议，测试者独立检查后通过产品RPC模拟用户确认；这些审核行为另行记录。不能把审核后任务存在说成AI未经批准直接更新日历。

邮箱内容使用离线MIME传输适配器，模型和产品工具为真实执行。不会真实发送邮件，不会登录Canvas提交作业，也不会写外部日历。独立验收不会修改模型输出、提示词或产物。原始失败、澄清和不确定答复均保留。

`semantic-review.json` 是人工逐轮语义复核，`verification-XX.json` 是每轮实际持久状态及结构检查，`turn-XX.json` 保留真实模型结果。可运行 `build-test-log.py` 重建时间线；该脚本不调用模型、不改业务数据库。未执行或尚未独立复核的轮次明确显示待完成。

官方摘要机制也经过实际核验：第6轮首次触发，第6–12轮共16个不同摘要事件；第12轮原始94条消息经官方摘要应用后为23条，历史备份实际存在。见 [summary-checkpoint-audit.md](summary-checkpoint-audit.md)。这些证据说明测到了摘要后的工作，不说明摘要不会遗漏；可观测token累计也不是完整账单或上下文窗口长度。

问题归因需分开看：PPT硬要求、报告语言和页数推理属于超出来源的模型判断；同会话的审批状态未刷新是持久状态读取缺口；只有标题的经验也能入草稿是内容质量校验不足，但人工审核保护没有失效。历史来源补回仅识别36字符ID而邮件ID为64字符、收件箱将空body列表对象直接打开，是已经定位的代码问题。截图来自原始快照，不用修复后图片覆盖旧表现。

来源跳转和收件箱阅读已完成窄范围代码修复；时间线末尾的**基线之后第16轮**是单独复测，84.35秒自然完成。原15轮请求、回答、状态文件及原截图哈希不变。模型只读了较新的目录邮件，三条旧引用没有重读，却已补回完整原始sources；修后真实应用也能从回答引用和收件箱两条路径打开同一首封邮件的完整正文。

这不是严格控制变量A/B：复测从15轮后的profile克隆，继续之前停在12轮的主会话，原话相同，但本地已多了后续邮件、参考日变为11/30。可归因的修复证据是旧引用无重读仍恢复、原授权来源逐字段匹配、实际UI点击读回成功。新答仍有“正文可能7页或9页”的错误，所以只判导航/取数修复通过，不宣称模型推理问题、审批状态读取或不确定性丢失已解决。见 [定向复测独立审计](fixes/followup/independent-followup-audit.json) 和 [修后实际界面操作](fixes/ui-stage-16/screenshots.json)。
