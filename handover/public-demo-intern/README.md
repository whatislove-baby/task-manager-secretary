# 全合成实习演示

本例为校园职业中心实习工作：同事周宁给实习生阿乔发来职业分享周报名表和活动安排，请整理简报。人物、单位、活动、通信和所有数值均为新编的合成资料。地址使用不可真实投递的 `.invalid` 域名。

仅输入一封合成 MIME 邮件、一个 CSV 和短 Markdown，未复制任何真实公司资料、既有业务脚本、规则、模板或其他案例文件。来源及字节哈希见 `input-provenance.json`。

用户请求见 `requests/01.json`：整理成一页简报，小表展示报名和剩余名额，写两句注意事项，保存 Word 和 PDF，检查后放入回复草稿。没有在请求中指定工具名或预写报告内容。

`run.py` 调用现有验收脚本，使用现有已授权模型和当前产品源码。独立 profile 为 `[local-test-profile] MIME 适配器；SMTP 和发送预检均被测试保护阻止。本例验证邮件附件到文档、检查及未发送草稿，不宣称真实邮箱收发通过。

首次用普通 Python 的预启动在凭据解密阶段失败，未进入模型、未生成产物，记录保留在 `preflight-01.json`。随后使用项目此前已授权的受信 Python 入口，不另行复制或导出密钥。

真实 API 执行记录见 [turn-01.json](turn-01.json)：94.91 秒自然完成，无模型重试，无产物手工修改；产品源码全程未变。生成一页 Word，原生转为一页 PDF，再检查并创建给周宁的双附件回复草稿，未发送。

独立审计结果：[verification.json](independent-audit/verification.json)，所有程序检查通过。独立审计脚本（内部留档）只读业务数据库、独立重新渲染产物副本，不调用模型、不修改文档、不补充模型输出。PDF 与独立 Word 渲染逐像素相同，也与原生转换缓存逐字节相同；原始邮件附件保留；草稿收件人与回复来源正确，实际附上两个当前文件，SMTP 记录为 0。

逐页目视与内容验收见 [review.md](independent-audit/review.md)。报名 42/34/30、剩余 18/6/20、总报名 106 人次和剩余 44 个名额均正确。报告明确区分报名人次与去重人数，未声称通知同学或加场。
