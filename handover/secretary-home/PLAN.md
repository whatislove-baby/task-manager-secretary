# 秘书主页完整流程验收计划

本轮所有人名、学校、机构、地址、邮件正文和数据均为新编的虚构资料。地址使用保留的 `.invalid` 域名。不会连接生产邮箱，不会 SMTP 发信，不会把旧私人业务资料带入测试。

## 测试边界

- 真模型：现有 OpenRouter 配置只在内存中使用；保留自然用户原话、完整工具调用、实际回复、持久化状态和失败记录。
- 收信：空的产品本地邮箱 → 产品实际 `ImapReader` → 产品刷新工具 → 本地保存 → 模型分类。仅 IMAP 服务器协议边界由可追踪的 MIME fixture 替代；不预先写入本地邮件，不冒称测过真实 QQ／学校邮箱联网。
- 文件：产品实际下载 MIME 附件、读取 CSV／Markdown、生成并检查 Word、转换 PDF、创建带附件的回复草稿。审计者只读输出，不替模型修文稿。
- 审批：日历变更由单独的审查操作确认，聊天说“记一下”本身不能充当已审批证据。邮件只能停在草稿。
- 每轮先冻结输入和源码摘要，后保存结果。失败不得覆盖；恢复使用新的记录，并明确是不是同一执行恢复。

## 自然对话流程

| 阶段 | 用户实际操作／原话 | 验收重点 |
|---|---|---|
| 1 | 打开固定秘书，说“刷新一下” | 原先本地 0 封，经 IMAP 原始字节导入 5 封；正确摘要课程与实习行动，普通活动／广告可折叠但原件仍可找回 |
| 2 | “先帮我记一下那个课程项目的截止时间，放到待确认。” | 同秘书上下文定位课程原信；待确认事项日期准确；审批前无正式任务，独立批准后仅一项 |
| 3 | “摄影工作坊那封是我想参加的活动，别当广告折叠了，放到需要处理里。” | 明确人工纠正分类并持久保存，保留原信，后续刷新不覆盖用户纠正 |
| 4 | 通过“单独处理这件事”提交“把顾老师要的报名简报做好，一页就行，带上 Word 和 PDF，回信先存草稿。” | 真正独立任务对话，有秘书父来源与原目标；CSV/MD 字节实际下载，内容正确、Word/PDF对应、逐页检查、一个双附件草稿，无 SMTP |
| 5 | 返回秘书：“刚才那份简报做到哪一步了？” | 读取子任务真实当前状态，明确草稿与已发送不同；有可继续处理的任务链接 |
| 6 | “再刷新一下” | 无新信、无重复任务/草稿/导入；简报已完成与邮件是否汇报是不同状态 |
| 7 | 在服务器加入教师同线程改期信，再说“刷新一下，课程如果改期就帮我同步一下。” | 新增一封；针对同一已有任务提出改期，审批后原任务 ID 保持、旧日期替换，不另建同名任务 |

阶段 2 若模型澄清，保留问题并用普通语言回答；若已有唯一课程指代，不要求机械澄清。阶段 4 若因可恢复网络故障中断，保留失败并走产品继续入口，不重写原话或注入正确答案。

## 与真模型分开的确定性检查

1. 401 封原始 MIME 分页刷新，检查产品实际分页、正文只导入一次和重复刷新去重；分类使用明确标示的离线 stub，不据此证明模型分类质量。
2. 首次登录掉线、恢复后重新刷新；部分成功的账户/邮件不丢失，错误可见。
3. 同一执行 ID 重放、同时重复刷新、服务重启后固定秘书 ID 与子任务关系不变。
4. 用户纠正分类之后刷新或重启，覆盖优先级与原件保留。
5. 审批前后任务数、草稿发送回执数，以及接收附件与源 MIME 的 SHA-256。

## 完成标准

“全流程完成”必须同时具备实际收信证据、分类与来源、独立审批后的同一日历事项、独立子任务和回到秘书后的状态、正确生成文件、真实双附件草稿及 SMTP 回执为 0。局部测试通过不替代此标准。接口目前待实现冻结，本文是计划，不是通过报告。
